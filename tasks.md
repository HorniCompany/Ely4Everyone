# Ely4Everyone: бэклог

Собран 2026-10-18 по коду репозитория (4 агента-разведчика + 1 критик, проверявший их выводы по коду) и по публичным данным (Modrinth, piston-meta, доки Fabric и Ely.by).
Пункты с пометкой «не проверено» - это выводы из чтения кода или догадки, их нужно подтвердить перед работой.

Размер: **S** - маленькая задача, **M** - несколько заходов, **L** - большая, **XL** - отдельный проект.

## Где мы сейчас

- Мод собран только под **1.21.11** (`gradle.properties`, `fabric.mod.json` `~1.21.11`), а README и roadmap всё ещё пишут 1.21.1.
- Minecraft уже на **26.3** (вышел 2026-09-15). 26.1.2 вышел 2026-04-09, то есть мод отстал на версию уже в день релиза.
- В GitHub issue #3 просят 26.2 (открыт с 2026-08-30).
- Modrinth: один релиз `0.1.0-alpha` (2026-04-14), ~1.2K скачиваний, 4 подписчика.
- Доли версий на Modrinth (загрузки Fabric API / Sodium / Mod Menu с июня 2026): 26.2 ~38-50%, 1.21.11 ~14-20%, 26.3 ~13-16%, 1.21.1 ~1-12%, 1.20.1 ~6%.
- Наша ниша: **«Ely.by-вход прямо в игре, в любом лаунчере, как Fabric-мод»**. На ely.by/load Fabric-варианта нет вообще. CustomSkinLoader, In-Game Account Switcher, MultiYggdrasil/combo-auth и лаунчеры (Legacy Launcher, ElyPrism) закрывают только куски.

## 0. Безопасность 🔴

- [x] **0.1 OAuth-вход можно угнать** (M, high) - **исправлено локально 2026-10-18, не закоммичено и не выкачено.** Вход переведён на RFC 8252 loopback + PKCE (`shared-auth/.../oauth/LoopbackLogin.kt`), state не логируется, токены сессии больше не ходят в URL, старые моды по умолчанию получают «обнови мод» (флаг `allow_legacy_poll_login`). Прошло состязательное ревью (14 агентов), подтверждённые замечания исправлены. Заодно закрыто 1.3 и часть 1.1 (таймауты запросов к auth-host). Осталось: выкатка сервера, релиз мода с поднятой версией, `limit_req` в nginx (5.3).
  - `auth/start` принимает любой `state`, который придумал клиент. Колбэк завершает его, не проверяя, кто начинал вход, а `auth/poll` отдаёт `auth_session_token` и Ely access token **любому, кто знает state**. Отдаёт 24 ч, повторно сколько угодно.
  - Атака: злоумышленник присылает игроку настоящую ссылку horni.cc → Ely.by со своим state. Игрок жмёт «разрешить», злоумышленник опрашивает poll и получает токены (scope `minecraft_server_session`). Refresh продлевает их бесконечно.
  - Вторая дорога туда же: мод пишет state в `latest.log` на INFO/WARN, а игроки выкладывают логи в чатах помощи.
  - Как чинить: привязать state к секрету, который есть только у клиента (verifier в стиле PKCE, обязателен на poll). Сделать poll одноразовым (с коротким окном на повтор после сетевой ошибки). Перестать логировать state. Токены передавать только в заголовках, не в URL (`issue-ticket`, fallback в `refresh`).
  - Код: `shared-auth/.../host/EmbeddedAuthHttpServer.kt:403-442`, `shared-auth/.../oauth/OAuthStateStore.kt:46-68`, `mod/.../auth/AuthWorkflowManager.kt:85,204,263,266,278`.
  - Чинить вместе с модом: нужен и серверный, и клиентский релиз.
- [ ] **0.2 Выход из аккаунта не отзывает сессию на сервере** (S, medium)
  - «Выйти» в моде удаляет только локальный файл. Утёкший `auth_session_token` остаётся рабочим и продлевается.
  - Нужен эндпоинт revoke, который мод вызывает при выходе, и «выйти везде».
  - Код: `mod/.../auth/AuthWorkflowManager.kt:106-118`, `EmbeddedAuthHttpServer.kt:98-160`.
- [ ] **0.3 Токены мода лежат открытым текстом в `config/`** (M, high)

  - Код: `mod/.../session/ClientSessionStore.kt:11,27,38,78`.
- [ ] **0.4 Скины: Ely перебивает настоящие скины, по HTTP и без проверки подписи** (M, high)
  - Для **каждого** игрока скин берётся с Ely.by, если он там есть, даже когда vanilla уже вернула подписанный скин Mojang. Кто зарегистрирует на Ely ник известного игрока, тот и решает, как этот игрок выглядит у пользователей мода.
  - Все видимые ники уходят открытым текстом на `http://skinsystem.ely.by`. Подпись текстур не проверяется (любая строка подписи = SIGNED), хост URL текстуры не проверяется. Значит, любой на пути трафика может подменить скин на произвольный URL.
  - Ник не URL-кодируется: ник с пробелом (например, у NPC) роняет `URI.create` прямо внутри миксина.
  - `exceptionally { vanillaFuture.join() }` блокирует поток пула.
  - Как чинить: брать Ely только когда vanilla не дала текстур / дала дефолтный скин, или для offline UUID. Сделать настройку приоритета (Ely первым / Mojang первым / выкл). HTTPS (проверено: `https://skinsystem.ely.by/textures/signed/...` отвечает 200). Принимать только домены Ely, проверять подпись ключом Ely.
  - Переписать заявление в README про «работает на любых серверах».
  - Код: `mod/.../mixin/client/PlayerSkinProviderMixin.kt:57,82,91-93`, `mod/.../skin/ElySkinResolver.kt:27,105,133-170`.

## 1. Сломано у игроков прямо сейчас 🟠

- [ ] **1.1 Сеть в игровом потоке без таймаутов = фризы** (S, high)
  - `TokenHealthMonitor.tick` в тике клиента делает блокирующий `HttpClient.send`. Кнопка «Обновить сессию» делает то же из потока рендера. У HttpClient'ов нет таймаутов, у `.join()` в тикетах тоже. Медленный хост замораживает игру.
  - Код: `mod/.../session/TokenHealthMonitor.kt:148,193`, `mod/.../ui/ElyAuthScreen.kt:146`, `mod/.../auth/AuthHostClient.kt:30,104`, `mod/.../identity/ElyAuthlibBridge.kt:16,46`, `mod/.../network/LoginQueryResponder.kt:72`.
- [ ] **1.2 Автообновление токена не работает после дня без игры** (M, high)
  - Клиент: личность активируется на старте только для ещё живого токена, а без активной личности монитор возвращает NOT_AUTHENTICATED и refresh не пробует. Это противоречит коммиту `fa30e2c` («auto-refresh tokens»).
  - Сервер: клиентские сессии удаляются через 24 ч (`ClientAuthSessionStore.kt:58-61,97-102`, TTL 86400 в `ProxyConfig.kt:79`), и refresh отвечает 404 `invalid_session` (`EmbeddedAuthHttpServer.kt:141-144`). Так что одной правки клиента мало.
  - Как чинить: отдельный долгий срок жизни refresh на сервере (например 30 дней, истекает только access-часть) плюс клиент решает по наличию `auth_session_token`, а не по активной личности. Нужен релиз и мода, и сервера.
- [ ] **1.3 «Попробовать снова» ничего не делает после ошибки** (S, medium)
  - После ошибки poll `pendingStateId` остаётся. Retry ничего не делает, а «Войти» отвечает «Вход уже выполняется». Заброшенная вкладка браузера = poll вечно.
  - Как чинить: retry отменяет старую попытку, у входа таймаут в несколько минут.
  - Код: `mod/.../auth/AuthWorkflowManager.kt:60-62,71-77,215,277-283`.
- [ ] **1.4 Упал Ely.by = не заходят и лицензионщики** (M, high)
  - На проксе нет try/catch вокруг запросов. Исключение или таймаут Ely в PreLogin не даёт дойти до Mojang. В hasJoined исключение Ely прерывает цикл до Mojang. Пока Ely лежит, Mojang-игроки и cracked с случайным UUID тоже не входят, ожидая до 10 с на запрос.
  - Как чинить: ловить по каждому источнику, идти к следующему, явно решить политику на время сбоя (fail-open может пустить cracked на премиум-ник, нужны тесты).
  - Код: `shared-auth/.../host/HybridAuthSupport.kt` (`send()`, `resolvePreLogin`, цикл hasJoined).
- [ ] **1.5 Release Sync в CI падает на каждом пуше с апреля** (S, high)
  - `release.yml` копирует `*-0.1.0-SNAPSHOT.jar`, а версия проекта `0.1.0-alpha`. Если бы он работал, он бы через `--clobber` молча перезаписывал файлы последнего релиза на каждом пуше в main.
  - Как чинить: релизы по тегу, версия из Gradle, Paper jar в релиз (если он остаётся), не хардкодить версию в `@Plugin`.
  - Код: `.github/workflows/release.yml:3-6,38-40,59`, `build.gradle.kts:8`.

## 3. Мод: фичи и удобство 🟢

- [ ] **3.1 Явный режим «Играть как Ely / как Microsoft» с перезапуском** (M, high, нужно решение по дизайну)
  - Сейчас при наличии Ely-сессии **каждый** вход идёт через Ely, а ключи профиля принудительно MISSING. Лицензионные online-mode сервера, вероятно, не пустят. Обход один: выйти из Ely.
  - Нужен видимый переключатель на титульнике и «перезапусти, чтобы применить», плюс понятная подсказка при отключении («этому серверу нужен Microsoft-вход»). Возможно, несколько сохранённых Ely-аккаунтов (In-Game Account Switcher с 5.7M скачиваний показывает спрос).
  - Заодно снимает противоречие с AGENTS.md: там сказано, что hot-swap сессии надо бросить, а код меняет живую сессию после входа, refresh и выхода, иногда из фоновых потоков (`AuthWorkflowManager.kt:247`). Решить: либо применять только на старте, либо делать swap в потоке клиента и обновить доки с доказательствами. Делать вместе с 0.5.
- [ ] **3.2 Подпись чата для Ely-игроков** (M, high, не проверено)
  - Мод выключает ключи чата у Ely-игроков. Сервер со стандартным `enforce-secure-profile=true`, вероятно, их не пустит. Ely в метаданных объявляет `feature.enable_profile_key=true`, эндпоинт сертификатов без токена отвечает 401, значит сертификаты, похоже, выдаёт.
  - Быстрый шаг: написать в доках, что серверу нужно `enforce-secure-profile=false`.
  - Большой шаг: получать сертификаты Ely (48 ч). Тогда мы будем единственными, кто работает на стоковом сервере.
  - Риски: примет ли эндпоинт токен со scope `minecraft_server_session`, доверяют ли серверы ключу Ely. Ошибка = кик при каждом сообщении в чат.
- [ ] **3.3 Понятный экран входа и переводы** (M, high)
  - Все строки захардкожены по-русски, файлов `assets/ely4everyone/lang` нет. На экране жаргон («auth-host», «horni.cc relay», сырые URL) и сырые исключения. Экран успеха обрезает UUID до 13 символов и показывает выбранный хост, а не тот, где реально сессия.
  - Минимум en_us, ru_ru, uk_ua. Ошибки переписать в «что случилось и что делать».
  - Код: `mod/.../ui/ElyAuthScreen.kt:135,309,386`.
- [ ] **3.4 Удобные точки входа** (S, medium)
  - Экран открывается только кнопкой на титульнике по жёстким координатам: она может налезть на кнопки других модов. Добавить пункт в Mod Menu (опциональная зависимость) и статус Ely на экране мультиплеера.
  - Код: `mod/.../ui/TitleScreenIntegration.kt:19`.
- [ ] **3.5 Не зависеть от одного relay на horni.cc** (M-L, high)
  - OAuth Ely требует client_secret, поэтому вход идёт через auth-host (по умолчанию horni.cc). Лёг horni.cc = не входит никто.
  - Варианты: прямой вход через authserver Ely по паролю как запасной режим (2FA как `password:totp`, только по желанию, с аккуратной работой с паролем), заметка о приватности и аптайме relay, статус relay в UI.
  - Источник: https://docs.ely.by/en/oauth.html, https://docs.ely.by/en/minecraft-auth.html
- [ ] **3.6 Кнопки «Сменить скин на Ely» и «Обновить скины»** (S, medium)
  - API загрузки скинов у Ely нет, поэтому кнопка просто открывает страницу скина. «Обновить» сбрасывает 5-минутный кеш скинов.
